# 本地候选版本

> 2026-10-09：按用户要求停止维护本地候选副本，`release/local-candidate-20261008/` 及其中的旧构建备份已清理。以下为历史构建与验收记录，目录和程序指纹不再代表当前可启动入口。当前开发与试用统一使用带前端资源的 `src-tauri/target/debug/translay.exe`，构建与正常启动方式见根目录 [README](../README.md)。正式 Release 程序保留；隔离托盘验收仍通过独立测试参数启动。

候选版本是当前工作区生成的 release 程序副本，供用户手动试用。源码仍维护在现有 `src/` 与 `src-tauri/` 中；它不增加窗口管理框架、设置项、业务分支或独立源码目录。正式程序名称、托盘和界面保持现状。

## 构建与目录

复用已有命令 `npm.cmd run app:build:exe`，只使用 `src-tauri/target` 构建。程序产物为 `src-tauri/target/release/translay.exe`。候选副本放在 `release/local-candidate-日期/`，这个目录已被 Git 忽略，不进入源码提交。目录仅包含：

```text
local-candidate-20261008/
  translay.exe           当前候选程序
  使用说明.txt           启动、退出与恢复旧版的方法
  build-info.json        构建时间、源码清单指纹、程序 SHA-256 与验证范围
  previous/
    translay.exe         本次构建前的旧程序备份
```

构建前核对正在运行的程序，保留旧构建并核验 SHA-256；现有安装版不被替换。构建后核验 Windows x64 GUI PE 头、候选副本与构建产物的 SHA-256 一致、备份保持完整，并检查 debug 验收标识在 debug 对照程序中存在、在 release 中不存在。静态核验不代表候选程序已经实际启动。

本轮使用当前整个未提交工作区构建，其中包含此前已有的改动。源码清单、Git 状态和构建日志记录在 `tests/artifacts/local-candidate-*` 中；不把这个候选程序描述为只包含本轮几个文件的独立提交。版本号沿用 0.4.0，日期和程序指纹区分本地构建，不发布安装包或 Release。

## 用户启动与恢复

1. 使用旧程序托盘菜单的「退出」结束旧程序。正常程序沿用单实例规则，如果旧程序仍在运行，双击候选程序可能激活旧实例。
2. 打开候选目录，双击该目录顶层的 `translay.exe`。启动后从系统托盘使用它。
3. 候选版按正常产品规则使用现有配置和 Windows 凭据，配置页的保存仍会生效；无需复制密钥、模型信息或用户数据。构建阶段没有启动程序、读取实际凭据或发起模型请求。
4. 若试用出现问题，从候选程序托盘菜单「退出」，再打开原来日常使用的程序。`previous/translay.exe` 是构建前旧产物的额外备份，不替代原有安装入口。程序备份不回滚试用期间主动保存的配置。

## 空间与保留规则

候选目录保留当前程序和一份旧构建备份，不复制源码、`node_modules`、`target`、用户数据或 WebView 缓存，不额外制作 ZIP 或安装包。每次更新记录实际目录大小和构建缓存变化。后续替换候选时先确认试用结果与要保留的旧版本，不自动积累更多旧包，也不未经确认删除用户原有程序或设计素材。

2026-10-08：候选 exe 为 14,589,952 字节（13.91 MiB），旧构建备份为 14,288,384 字节（13.63 MiB）。两份程序合计 27.54 MiB，说明和元数据仅数 KiB。构建前已有 Rust debug/release 缓存合计约 9.16 GiB；本次 release 缓存增加 3,257,582 字节（3.11 MiB）。缓存与候选目录分别记录，不把既有缓存算成本轮新增程序体积。具体证据见 [本地候选构建报告](../tests/artifacts/local-candidate-report.md)。
