# 学习模式术语一致性：可行性检查

日期：2026-09-20。范围为现有代码静态检查，没有修改运行逻辑、采集新的阅读内容或调用模型。

## 现有信息

| 信息 | 代码现状 | 能否作为文章边界 |
| --- | --- | --- |
| 应用名、PID、窗口句柄 | ForegroundContext 持有 | 只能标记窗口，不能区分同窗口内的文章或标签页 |
| 窗口标题 | capture 时读取，但只在无法取得进程名时作为应用名回退，不单独保存 | 目前不可用；即使保存，也只能辅助判断，不能单独作为唯一文章标识 |
| 选中文字及位置 | SelectionCapture 提供，位置可缺失 | 不能唯一标识文章 |
| 邻近上下文 | 学习模式、单一 UIA 文本范围时，尝试各读取 480 字符单位，读取失败允许缺失 | 可帮助消歧，不能证明多次选区来自同一文章 |
| 剪贴板回退 | 只有所选文字，上下文和选区位置为空 | 缺乏文章识别信息 |
| URL、文件路径、文档标识 | 当前捕获结果没有这些字段，也没有文档身份提取链路 | 尚不具备可靠文档隔离条件 |

## 术语链路

TranslationRequest 已有 glossary 字段，但构造时为空。学术请求另行生成 AcademicTranslationInput，当前只发送 inputKind、原文和相邻上下文，不包含 glossary。因此不能仅向现有字段填入内容就认为术语记忆已生效。

当前学术提示词要求术语一致，但没有跨请求的源词—译词存储，也没有可靠的译词对齐/提取机制。自动从整段译文猜测映射，或从多义词解释直接挑第一个义项，会把错误传播到后续请求。

## 结论与建议

暂不直接接入自动跨段落术语记忆。下一步若推进，先做开发专用的“文档识别可行性探针”：在用户实际使用的浏览器与 PDF 阅读器中验证可获得的文档身份。这里只是后续方案，尚未编写或运行探针。

1. 优先研究选中文本所属文档的 URL/文件身份等证据；标题、窗口句柄只作辅助。缺少可靠身份时禁用跨请求记忆。
2. 不遍历或记录全部标签页，不采集整篇内容。诊断报告尽量只记录身份类型、是否稳定、是否变化；不保存标题、URL、路径及正文原文。
3. 验证同篇连续划词、切换不同文章、同名文章、同窗口导航、PDF 换页/换文件、关闭重开，以及 UIA 失败转剪贴板。身份不确定时安全回退为现有单次翻译。
4. 身份隔离证明可用之后，再评估少量高置信术语映射；既有译法仅作参考、上下文优先，不从多义词列表自动学习。限定内存、数量与有效期。
5. 接入时需把参考术语显式纳入学术模型输入与提示词，并确认译文缓存键包含实际使用的术语集合。日常模式与公式处理不受影响。

本轮无需重新生成可执行文件；当前可用版本保持不变。

## 后续实测更新

已完成开发专用探针及 Edge / Chrome 自动采样，详见 [文档识别探针](document-probe.md)。32 个样本验证了 URL 候选、歧义拒绝和单页导航边界；同网址替换正文仍无法区分，活动文档归属也未完整解决。上文“尚未编写或运行探针”仅描述最初静态检查阶段。当前仍不接入术语记忆。

补充：Document RuntimeId 能观察到刷新，但无法检测同 URL 的文本替换或整页 body 重建。仅桌面 UIA 的 URL + RuntimeId 组合仍不满足自动文章隔离。后续可评估网页侧文档切换信息或显式阅读会话；没有新增扩展依赖或正式入口。
