# 启动提示

已将确认的折页 T 与 Translay 字样连续掠光方案接入应用。提示固定在 Windows 主显示器完整屏幕中心，透明、无边框、不获取焦点，并穿透鼠标操作。

## 2026-09-23 边缘染色底片

正式启动背景采用选定的 C 方案：204 × 88 CSS px 胶囊保持原位置和圆角，灰绿与雾紫由两侧大半径径向渐变轻轻向内晕开，中央仅保留约 0.095 alpha 的中性色层；径向遮罩中心约 0.49、边缘约 0.31。阴影为 `0 2px 10px rgba(49,64,62,.025)`。这些参数只作用于独立的 `.startup-backdrop`，T、艺术字、掠光、状态文字与入退场时序未改。渐变静止，不使用 `backdrop-filter` 或跨窗口原生毛玻璃。

下方较早日期的底片数值与截图为历史记录，不代表当前外观。

## 2026-09-12 外观更新

- 独立 `.startup-backdrop` 图层：216 × 88 CSS px 胶囊，灰绿到雾紫渐变，底色不透明度 45%。图标及字样尺寸不变。

- 最终 release 编译成功，浏览器回归验证了胶囊尺寸、位置、底片完整退场及既有启动状态。前端 91 项测试通过；本轮 Rust 160 项通过、1 项在线测试跳过。Windows 最终版本截图确认无实验黑底；原生多屏/DPI 与毛玻璃兼容性未宣称验收通过。

## 背景辨识度检查（2026-09-12）

使用生产构建的实际启动组件，在 Chromium 中合成纯白、深灰与密集文字背景，固定到“已就绪”状态以排除入场和退场透明度的影响。此项是可控背景的视觉检查，不是三种真实桌面的 Windows 原生验收，也没有测试全部壁纸或 DPI。

- 浅色背景：标志和胶囊轮廓清楚，状态文字可读。
- 深色背景：45% 透底后的底片偏暗，字样和状态文字与底片的明度接近，辨识度不足。
- 密集文字：背景字符透入标志与状态区域，阅读受到干扰；没有原生模糊时，仅保持 45% 底色不能保证复杂背景可读。
- 试验过中央局部补浅色、略加深字样的方案。虽有改善，但深色背景出现明显浅色光斑，复杂文字仍有干扰，未采用，未修改正式样式或重新生成 release。

可复现检查：在执行生产前端构建后运行 `node tests/browser/startup-background-review.cjs`（需 Playwright），输出 `tests/artifacts/startup-background-review.png`。脚本结束自动关闭浏览器和预览服务。建议后续比较更均匀的局部遮盖与字样细微衬边，明确可读性和通透度的取舍后再接入。

衬边试验：使用 `--edges` 参数生成 `tests/artifacts/startup-edge-comparison.png`，上排为生产原样，下排只给字样和状态文字添加很浅的柔边（不改底片与文字配色）。浅色背景变化很小，深色背景轮廓更明显，但字样出现空心描边感；密集背景仍然有字符干扰。此方案不建议接入，正式组件与 release 保持不变。该视觉对照不代表已通过通用可访问性对比度验收。

## 显示规则

- 正常启动：灰绿到雾紫的光带从 T 延续到字样，只播放一次；底部文字使用静态渐变色。
- 本地初始化完成且模型配置可用时显示“已就绪”。快速启动也会等待掠光完成；初始化较慢时静态等待，显示“正在启动”。
- 配置不可用时显示“待配置”，退场后打开设置。
- 重复打开通过 Windows 命名事件通知已有进程，短暂显示“已在运行”，不重复完整掠光、不创建第二个常驻进程。
- 使用 `--autostart` 或 `--background` 启动时保持安静。这些参数不负责注册系统自启动；自启动入口需要显式传入参数。
- 支持系统减少动态效果偏好；图标、字样和状态分阶段淡出。每轮提示有独立编号，旧计时器不会关闭新一轮提示。

“已就绪”依据 Rust 启动流程中窗口、配置、托盘、输入监听与快捷键初始化完成后的状态，以及已有模型配置的本地可用性检查。它不代表模型服务已经通过在线请求验证，也不额外调用模型。浮层前端的独立就绪握手不属于这一判定。

本地初始化结束后启动 15 秒退场保护，避免启动提示前端异常造成长期置顶。保留隐藏提示窗口以响应重复启动。

- 采用用户确认的 light-reveal 预览：204 × 88、44px 圆角胶囊；独立底片使用灰绿至雾紫渐变，遮罩不透明度由中央 65% 向边缘 45% 过渡，不启用原生桌面模糊。

- 状态文字移出遮罩区域。退场先隐藏状态，140ms 后从 y 向 T 消隐，耗时 850ms；底片于 840ms 开始淡出，1230ms 后才通知原生隐藏窗口。
- 重复启动直接显示完整字样；减少动态效果模式使用淡出。真实就绪判定、主屏居中、托盘和翻译行为保持原有逻辑。

## 启动反馈提前与页面轻量化（2026-09-12）

启动提示改为独立的 startup.html，通过 mountStartup.ts 复用原来的状态时序与 CSS，不加载 React。正式构建浏览器实测该页面的全部 JavaScript 为 4567 字节（约 4.6 KB），此前主入口约 196 KB，另有启动与 IPC 模块。这是脚本体积对比，不是冷启动耗时测量。

原生创建透明提示窗口后即按主屏居中显示，再创建其余隐藏窗口；只有可见冷启动会传入 present=1。图标解码后可先播放动画，不必等待主线程返回初始化状态；已就绪仍由原有真实状态决定，动画不因状态返回而重新播放。后台启动不提前展示，重复打开保持原有简短提示。

验证：91 项前端测试、160 项 Rust 测试通过（1 项在线测试跳过）。生产浏览器回归新增了阻塞初始化 IPC 时提前呈现、独立入口脚本体积上限、后台静默检查；原有时序、重复打开、退场、CSP 与资源检查均通过。Windows 正式程序已启动并退场，重复启动显示完整标识与“已在运行”，维持单实例。未测量跨机器冷启动耗时；Windows 启动进程与 WebView2 的短暂等待仍可能存在。

正式入口仍为 src-tauri/target/release/translay.exe。未修改模型配置、翻译逻辑或动画配色，也未增加预启动常驻进程。

## 首帧衔接与重复定位修正（2026-09-12）

本轮保持样式、配色、动画曲线与时长不变，仅处理启动衔接：
- 启动窗口已显示时，前端 reveal 握手不再重复设置尺寸、位置和 show，避免动画途中再次触发原生布局；隐藏后重新打开仍按当前主屏定位，只在尺寸或坐标实际不同时更新。
- 除图标和字样外，入场前也等待 CSS 使用的 T 掠光遮罩解码，避免首次光效资源迟到。
- 播放及重复打开不再克隆替换图像节点，保留已经解码的节点，重置 CSS 播放状态。

验证：91 项前端测试、160 项 Rust 测试通过（1 项在线测试跳过）；正式构建后的浏览器回归通过，新增遮罩延迟加载时禁止提前播放与多轮播放保持图像节点的检查。正式 exe 已更新。原生截图用于确认启动画面正常显示，不代表已量化帧率或完全消除冷启动等待；Windows/WebView2 初始化仍有成本。
