# Edge / Chrome 文档识别探针

更新：2026-09-20。开发专用实验，尚未接入术语记忆。

## 运行范围

入口为 `tests/browser/document-probe.cjs`，运行前构建 debug 可执行文件并提供 Playwright。脚本自动新建独立 Edge / Chrome、本地合成页面和探针，结束后关闭这些浏览器、探针与本地服务，不要求用户按键验收，不连接个人标签页。

探针只在 debug 编译，必须显式启动；不初始化正常应用、模型配置、托盘或选区监听，不自动翻译，不读剪贴板。正式版的前台校验、翻译行为与现有可执行文件保持不变。

## 证据如何取得

脚本通过浏览器调试连接取得自有浏览器 PID。探针校验进程确为 msedge/chrome，并绑定其最大可见顶层窗口。这个后台入口没有正式前台捕获的焦点条件，因此只能验证测试专用路径，不能外推为正式翻译入口的完整验收。

后台路径在所绑定窗口的 UIA 子树中寻找文档候选，最多检查 1024 个元素、取 8 个可见文档。多个候选有选区或选区读取失败时，返回 `PROBE_AMBIGUOUS_SELECTION`。枚举上限、缺失节点和无 TextPattern 文档仍是限制，不能把未发现冲突解释为穷尽证明。

复用 SelectionService 捕获选区后，沿其控件祖先查找最近 Document，读取 ValuePattern / LegacyIAccessible Value 与名称。不读地址栏。仅 http、https、file 地址作为候选，保留 query 和 fragment；两个 Value 矛盾时退回未知。阅读器壳地址不证明其内嵌 PDF 身份，PDF 尚未验收。

脚本提供的预期文字和 URL 只在捕获完成后比较，绝不参与候选选择。报告仅保存比较布尔值、场景名称、身份来源与进程内随机哈希，不保存原文、标题、URL 或文件路径，也不调用模型。不同探针进程的哈希不可直接比较。

## 最新实测：32 个样本

Edge、Chrome 各 16 个场景，启动时启用 accessibility，使用本地合成网页。

| 检查 | Edge | Chrome |
| --- | --- | --- |
| 两个测试页面属于同一浏览器窗口（CDP 核对） | 是 | 是 |
| 同篇换段、跳转同标题不同文章、返回 | 文字与文档匹配 | 文字与文档匹配 |
| 多个文档残留选区 | 6 次均拒绝歧义 | 6 次均拒绝歧义 |
| 清除其他文档选区 | 文字与文档匹配 | 文字与文档匹配 |
| 关闭第二标签页后独立测试正文替换、hash 路由与刷新 | 4 次文字与文档均匹配 | 4 次文字与文档均匹配 |
| hash 改变能否区分 URL 候选 | 能 | 能 |
| 刷新后 URL 候选是否保持一致 | 是 | 是 |
| 网址不变、正文替换，URL 候选能否发现文章变化 | 不能 | 不能 |

合计 20 个明确选区同时匹配文字与文档，12 个歧义场景安全拒绝。自动检查通过，但这仅说明探针符合上述预期，**不表示文章身份已经可靠**。同网址正文替换是明确记录的能力缺口，不应包装成通过。

## 基线与结论

保留 `tests/artifacts/document-probe-selection-baseline.json` 作为加防护前的证据：两个浏览器均出现后台残留选区导致文字和文档同时不匹配；等待 2 秒没有解决，清除另一页选区后恢复。最新 CDP 检查确认两个页面处于同一窗口，排除了测试页面分属不同窗口这一解释；仍未确定为何这些文档同时被 UIA 视为可见。

此前混在残留选区里的正文替换/hash 测试不能独立下结论，已用关闭第二标签页后的四个场景补测。

当前只保留两份有用途的报告，不额外产生重复单浏览器报告。所有记录仍为 `terminologyEnabled: false`。

## 下一步边界

1. 继续研究选区所属活动文档与真实前台焦点的一致性；后台拒绝歧义不是活动文档识别方案。
2. 需要文档生命周期或导航证据才能应对同 URL 换正文；URL、标题或所选段落的哈希都不足以单独承担文章身份。
3. PDF、iframe、浏览器默认 accessibility 配置、导航期间捕获以及关闭重开尚未验收。
4. 在这些边界得到可靠处理之前，不接入跨请求术语记忆，沿用现有单次翻译。

## 文档节点与系统焦点补测（34 个样本）

在每个浏览器原有 16 个场景之后增加“同网址替换整个 body”，并记录文档 RuntimeId 的进程内哈希、文档自报焦点状态、是否包含系统全局焦点，以及实际窗口是否处于前台。不会读取整篇正文来制作指纹。

两个浏览器的结果一致：

- 文本替换、hash 路由变更和整个 body 重建均不改变 Document 的 RuntimeId。
- 刷新改变 RuntimeId。它可作为节点生命周期的辅助线索，但不能证明文章是否变化。
- 初轮前台诊断中，旧标签页与当前标签页均自报 HasKeyboardFocus=true；沿系统 GetFocusedElement 的祖先链查找，只有当前文档匹配。因此不能直接使用文档的 HasKeyboardFocus 属性判定活动页。

开发探针新增候选规则：仅当窗口实际处于前台、焦点读取明确且只有一个文档包含系统焦点时，缩小到该文档；否则保留原有歧义拒绝。此规则只存在于显式 debug 探针路径，尚未接入正式选区流程，也尚未完成前台验收。嵌套文档、焦点在捕获期间变化、活动页没有选区等边界仍需验证。

最新常规复测 `tests/artifacts/document-probe-browsers.json` 中，34 次采样均发生在后台：22 次明确选区匹配，12 次歧义拒绝。它验证了后台保护仍有效，不能算作新焦点选择规则通过。

新增可选开发参数 `node tests/browser/document-probe.cjs --foreground`，仅针对自有测试浏览器调用正常的 SetForegroundWindow 请求，不强行绕过系统前台锁。专门复测时 Windows 未给予前台，`requestedForegroundVerified=false`，测试正确返回失败。该结果独立保存在 `tests/artifacts/document-probe-foreground.json`，不覆盖常规报告。不再重复尝试相同的前台请求，也不要求用户代跑命令。

Rust 检查：179 项通过、1 项忽略，release 库检查通过。测试浏览器、探针和服务由脚本退出清理。

### 实现决策

当前证据不支持只用桌面 UIA 自动维护“同一篇文章”的术语记忆。要继续实现，需要能报告文档切换的网页侧信息，或由用户明确控制的一次阅读会话；这两种方案均未接入，需先确定产品取舍。不能把整篇内容哈希、选区变化或短超时当成可靠的文章隔离证明。
