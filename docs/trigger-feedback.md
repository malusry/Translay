# 翻译触发反馈

未选中文字时显示中性的“请先选择文字”，隐藏重试入口，采用小浮层和 2 秒停留时间，继续遵守既有悬停阅读保护。仅 UIA 明确空选区且复制未产生新内容、或复制内容为空时使用这个提示；超时、前台变化和应用不支持读取等异常不冒充空选区。

正在翻译时再按快捷键，使用独立的可取消选区读取会话核对内容，不立即取消模型任务或重绘浮层。同一窗口／进程、原文、有效学术上下文与配置均一致时复用进行中的任务；如果核对期间该任务刚刚成功完成，也保留结果。不同选区进入原有新请求流程，旧结果仍受请求编号保护。划词图标入口采用相同比较规则。

比较选区失败时保留原有翻译进度。新触发、重试和主动取消都会使旧的核对结果失效。此机制不延迟正常首次读取，也不增加配置选项。已经显示完成结果后主动再触发，仍走原有翻译／缓存流程。

验证包含 Rust 的原文／上下文／窗口／配置差异、读取会话隔离、错误分类及提示停留策略；前端状态测试和实际 Overlay 浏览器组件回归验证中性提示、错误重试入口、加载和结果切换。自动化未调用真实模型服务，不代表所有外部应用的快捷键选区获取均已验收。

## 任务状态与接替规则（2026-10-07）

`translation_task.rs` 的 `TranslationTask` 是任务身份、独立核对会话、当前翻译身份和失败重试原文的唯一持有者。它只作决定和更新内存，不调用 Tauri、窗口、选区读取或模型。`CaptureCoordinator` 执行决定，负责读取、模型启动、前台检查和显示；`LatestCaptureStore` 仍是浮层阶段及结果快照的唯一持有者，新模块不复制一套显示阶段。

| 事件 | 决策与状态变化 |
| --- | --- |
| 首次快捷键／完成后再触发 | 立即建立新捕获代次，不额外核对；完成后仍走原翻译／缓存流程 |
| 翻译中再次快捷键 | 只替换独立核对会话，不取消翻译、不重绘加载浮层 |
| 核对成功／图标提交选区 | 同窗口、进程、原文、有效上下文及完整 `ModelConfig` 相等才复用；否则建立新任务 |
| 核对期间翻译成功 | 有效核对可复用已经完成的结果；后来主动点击图标不能借此扩大去重 |
| 核对失败 | 不改变当前翻译或显示 |
| 新任务／重试／主动取消 | 使旧核对失效；新任务和取消同时使旧翻译代次失效 |
| 翻译回调 | 提交边界重新验证代次；旧成功和旧失败都不得更新显示或重试原文 |
| 捕获失败重试 | 原子地预留新捕获代次，然后重新读取；重复旧重试不再启动第二次捕获 |
| 翻译失败重试 | 一次性消费匹配请求的完整 `TranslationRequest`；保留原文、上下文与模式，不读取后来选中的文字；再次失败可再重试 |

上下文比较继续通过 `TranslationRequest::with_academic_context`：学习模式去掉两端空白、空字符串视为无上下文，日常模式忽略上下文。配置比较保持原有完整相等规则，本次没有缩小或扩大配置去重范围。

### 并发边界

请求编号区分代次，取消标记供读取链路协作退出，两者共同决定回调是否仍有效。核对使用独立 `CaptureSession`，核对开始不会取消模型任务。模型请求没有接入该取消标记：过期结果被拒绝，不代表底层 HTTP 请求已终止。

协调器保留原有 `coordination` 提交门：取得显示／配置快照后，短暂获取任务锁作决定；释放任务锁，再调用浮层。嵌套顺序为 `coordination → task → CaptureSession`，或 `coordination → overlay.lifecycle → LatestCaptureStore / layout`，不反向获取。前台窗口检查也在任务锁之外。网络、UIA、剪贴板读取及异步显示门等待不持有协调门或任务锁；原有窗口显示提交仍在协调门内，以防“验证后解锁，再无条件显示”的竞态。本次不重写浮层生命周期。

附带修复既有接替间隙：首次触发的决策和新代次建立不再分属两个临界区；`overlay.begin_request` 也随新代次在同一协调临界区提交，防止较旧触发晚到时重置新浮层的悬停状态。捕获重试同样在验证后立即预留代次。
