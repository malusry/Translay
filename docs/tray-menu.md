# 托盘右键菜单（A 版）

采用紧凑的原生感布局：164 × 136 CSS 像素，8 像素圆角、细线图标、轻分隔线，支持系统明暗主题。保留模型切换、划词图标开关、配置和退出。左键单击切划词图标，快速双击切日常／学习模式；托盘原图与“侧向叠合”图案分别表示开启与关闭，悬停显示模式和图标状态两行，详见 [托盘状态规则](tray-mode-feedback.md)。

菜单使用独立透明窗口，按点击位置所在显示器的完整屏幕边界和 DPI 定位；优先将菜单可见左下角对齐托盘图标中心，向右上方展开；右侧不足则改为向左展开，图标矩形无效时回退到点击坐标，空间不足时向下并限制在屏幕内（允许覆盖任务栏）。方向键及 Home/End 导航，Enter/Space 激活，Escape/Tab 收起。失焦和点击透明边缘收起；关闭请求仅隐藏窗口，以便再次打开。

每次打开分配 generation。原生端只接受当前且尚未关闭的会话操作，避免重复执行和旧事件影响新菜单。模型不可用时禁用切换；开关继续使用现有持久化入口。前端完成渲染后通知显示，隐藏 WebView 的动画帧暂停时有定时器兜底。

2026-10-09 启动规则：每个新的正常进程加载模型配置后，在内存中将划词图标设为开启；先前保存的关闭状态不再决定下次启动状态。启动读取不额外写入配置文件，其他模型字段、模式和超时沿用原值。运行中的托盘开关仍通过现有入口保存，模型保存／模式切换及配置窗口重开保持本次开关；已运行实例再次收到打开请求也不会重置。测试与构建证据见 [启动默认开启报告](../tests/artifacts/selection-startup-enabled-report-20261009.md)。

验证：Rust 单元测试包含负坐标显示器和 100%～200% 缩放的边界定位。`tests/browser/tray-menu-regression.cjs` 在独立 Edge 中运行真实 React 组件、模拟 IPC，覆盖布局、主题、键盘、禁用状态、四项操作映射、重复点击、旧事件隔离和透明边缘关闭。模拟 IPC 不代表真实 Windows 托盘点击、焦点切换或多屏视觉验收已完成。

本轮扩展验收不改变正式功能，不重新发布安装包。

菜单打开时焦点停留在容器，不默认高亮任何项目；方向键导航才显示焦点，鼠标移动恢复悬停反馈。

2026-10-08 字体整理：菜单「配置」使用得意黑，其余操作文字使用 Noto Sans SC；仍为 164×136、13px 字号。字体本地预载完成后沿用原显示通知，旧加载回调检查会话；失败记录警告并回退系统字体，继续允许显示与操作。配置页字体分配、资源体积与验证见 [界面字体](ui-typography.md)。





修正任务栏场景：菜单边界使用 rcMonitor，不使用排除任务栏的 rcWork，否则最终裁限会把图标原位菜单向上推。回归测试覆盖底部任务栏图标与 100%～200% 缩放。


配置窗口死锁修复：Windows 下同步 IPC 命令和事件回调不能创建 WebView。所有配置打开入口均经 windows.rs 的 blocking worker 创建，显示／恢复／聚焦再投递到窗口线程；托盘命令保持异步。不能把 build() 放进窗口线程派发函数中。

## 原生连续操作验收

在项目目录运行 `./tools/tray-menu-acceptance.ps1`。脚本构建调试版，运行仅调试版支持的 `--tray-menu-smoke`，核对报告和进程正常退出，然后清理隔离目录。已构建时可加 `-SkipBuild`。

测试通过真实 React 按钮和 Tauri IPC 验证：配置打开／最小化恢复 6 次；划词开关切换、运行状态及落盘 4 次；本地／API 双向切换及落盘 4 次；缺少凭据时禁用；Escape 和透明边缘关闭各 3 次；旧会话操作隔离；原生失焦关闭；再次打开及退出。2026-09-26 已通过，结果保存在 `tests/artifacts/tray-menu-native.txt`。

启动规则验收复用同一程序：以虚拟关闭配置经过正式启动加载函数读取，确认不改写文件、划词管理器开启、实际原生托盘图案和提示为开启，然后主动关闭并继续已有关闭状态、切换、窗口和退出断言。手动入口仍使用原有开启 fixture；没有启动正常程序来读取日常配置。

配置与 WebView 缓存在 `tests/artifacts/tray-menu-sandbox`，不读取用户配置。虚拟凭据仅关联包含测试进程 ID 的 `.invalid` 域名，结束时删除；35 秒看门狗防止死锁遗留测试进程与虚拟凭据。测试不发起模型请求，不注册用户快捷键或启动划词监控。

覆盖边界：菜单通过真实窗口打开函数驱动，点击通过 DOM 触发；未操作 Windows 隐藏托盘面板，也未完成真实多屏视觉验收。配置窗口生命周期通过不等于配置表单所有功能通过。

## 窗口生命周期与职责（2026-10-08）

本轮只整理托盘菜单和配置窗口。配置的三个打开入口是托盘「配置」、启动提示结束后的首次配置引导、`--settings`。隐藏入口是配置按钮／Escape 的 IPC，以及原生关闭请求。其他窗口的生命周期不变。

| 模块 | 归属 |
| --- | --- |
| `app/windows.rs` | 配置窗口的唯一创建／打开流程、并发请求合并、恢复与聚焦、隐藏／最小化及打开失效；两个窗口共用的窗口线程投递小函数 |
| `app/tray_menu.rs` | 启动时创建并复用菜单窗口、generation 会话、定位、绘制握手、关闭、动作认领与进行中保护 |
| `app/tray.rs` | 托盘事件与既有业务动作；配置动作调用统一打开流程，其余动作在 blocking worker 执行 |
| `app/startup.rs`、`app/mod.rs` | 同步启动入口只派发配置打开请求，不等待 WebView 创建；注册状态与命令 |
| `app/shutdown.rs` | 先使菜单／配置请求失效，再沿用取消翻译与注销快捷键流程，最后在窗口线程隐藏窗口并退出 |

配置打开先认领一个进行中请求；尚未创建时在 blocking worker 创建隐藏 WebView，已有窗口则复用。重复请求等待同一操作的完成和结果，不额外创建，也不重复排队聚焦。窗口线程刷新既有 DPI 图标、恢复最小化、显示、聚焦。创建、显示、线程派发或 worker 失败都会释放进行中状态并通知等待者，下一次明确打开可重试。

隐藏和最小化会使之前的待显示请求失效。若用户在隐藏之后明确请求重开，但旧 worker 尚未结束，新请求先等待它释放创建保护，再打开；再次隐藏或退出会取消这个新请求。该等待由完成通知驱动，不依赖 sleep、轮询或失败自动重试。

关闭请求继续阻止销毁并隐藏同一窗口。重开不重新挂载 React、不重新加载表单。普通未保存字段继续保留；配置页关闭按钮和 Escape 继续清空未保存的 API Key 输入及其编辑状态；原生隐藏／关闭和最小化仍只执行原生动作。已有模型后端变更事件的表单同步规则、保存与凭据逻辑均不变。

菜单每次打开分配 generation，完成定位及 React 绘制握手后显示并聚焦。关闭／显示／绘制确认在窗口线程串行处理，状态锁只用于状态决定。Escape、透明边缘和原生失焦仍隐藏窗口；原生失焦还核对当前可见性和实际焦点，避免旧失焦通知关闭已重新获得焦点的菜单。动作先验证会话并一次性认领，标记会话关闭、隐藏菜单，然后执行；直到动作的完整结果（包括配置聚焦或模型刷新）返回，才接受下一次打开。完成或失败均释放动作保护。模型刷新关闭请求携带派发时的 generation，迟到刷新不会关掉新会话。

退出使两个状态不可再次认领；已排队的创建前检查、绘制确认、动作和显示均失效。已经进入原生创建的调用不能强行中止，但其显示阶段会重新检查失效状态，保持隐藏并随应用退出清理。最终隐藏与显示共用窗口线程，避免清理后被迟到的显示重新打开。未引入通用窗口框架或新设置项。

## 本轮验证

修改前：Rust 格式、类型检查、208 项 Rust 测试（1 项忽略）、95 项前端测试、菜单浏览器回归和原生连续操作全部通过。初次沙箱执行前端测试遇到 esbuild 子进程 `EPERM`，浏览器脚本默认找不到 Playwright；使用已有打包 Playwright 与沙箱外隔离执行后取得有效基线，未安装或升级依赖。

修改后证据分层如下，完整记录见 [窗口整理验收报告](../tests/artifacts/window-lifecycle-report.md)：

- Rust 单元测试：配置打开互斥／共用结果、失败和 panic 后释放、隐藏失效及退出拒绝；菜单动作一次性认领、旧会话、动作期间拒绝新开、失败和退出后的状态。保留定位与模式切换测试。单元测试不验证原生窗口行为。
- 浏览器模拟：现有菜单布局、明暗主题、无默认首项高亮、键盘、四项映射、重复点击与透明边缘关闭；新增旧绘制回复不抢新会话焦点、旧动作完成不解除新动作 busy、IPC 失败后重开。另运行既有启动提示与托盘模式反馈回归。IPC 为模拟，不作为 Windows 焦点证据。
- 原生验收：复用 `tools/tray-menu-acceptance.ps1`，验证同步回调派发后 worker 线程与窗口线程不同；12 次并发首开、原生窗口枚举只有一个配置窗口、HWND 始终一致；创建前／显示前受控错误后可重试；普通草稿关闭重开保留；隐藏与未完成打开竞争；原生关闭、页面关闭、Escape 隐藏；菜单打开配置、隐藏、重开及最小化恢复并聚焦共 6 次；动作等待已有配置打开；模型和划词开关各 4 次落盘；旧 action／close／paint；原生失焦后重开；真实退出动作及迟到窗口操作失效。原生点击通过 DOM，菜单打开通过真实打开函数。

错误注入只在 debug Rust 钩子处返回错误，验证实际打开流程的错误传播与状态恢复，不模拟系统资源损坏。退出验收仅在 debug 程序拦住一次真实 ExitRequested，以便检查实际 ShutdownCoordinator 隐藏之后的迟到操作；断言结束放行退出并检查 exit=0。正式程序不包含钩子、探针或退出拦截。

原生报告为 `tests/artifacts/tray-menu-native.txt`，包含虚拟凭据删除核验、正常进程退出和隔离配置／缓存清理证据。未调用真实模型，未读取或修改用户配置。Windows 隐藏图标面板中的人工右键操作、真实多显示器视觉效果及其他缩放比例的实机体验仍未验证；当前可用 UI 工具未开放 Windows 原生桌面控制，不能把程序化打开菜单记为这些项目通过。

## 简化的人工托盘验收

运行 `./tools/tray-menu-acceptance.ps1 -Manual`，已构建本轮调试版可加 `-SkipBuild`。复用上述原生验收程序，保留真实托盘事件、菜单、配置窗口及左键模式反馈；不会自动打开菜单。鼠标悬停测试图标时，提示为「Translay · 手动测试（临时数据）」，与日常程序区分。测试配置为虚拟模型，浏览器缓存位于 `tests/artifacts/tray-menu-manual-sandbox`；不启动翻译、划词监听或用户快捷键。配置页的保存、连接测试、凭据修改与外部链接命令未注册；凭据状态只允许查询本次虚拟地址，切换到真实提供商也不读取用户密钥。这个入口只验收窗口操作。

已有本轮调试构建时，也可在资源管理器中双击 `tools/tray-menu-manual.cmd`。它只调用上述脚本的 `-SkipBuild -Manual`，沿用相同隔离、会话保护和清理流程。测试期间保留启动的命令窗口，结束时在测试托盘菜单点「退出」。

用户按以下步骤操作即可：

1. 点 Windows 任务栏的 `^`，找到提示带「手动测试」的图标，右键打开菜单。如果图标已在任务栏外层，只验证了外层托盘，仍应记录隐藏面板未验证。
2. 点「配置」，用右上角关闭按钮收起配置，再右键测试图标打开菜单，重复两次。可顺手最小化配置后再点「配置」，检查恢复。
3. 菜单打开时按 Escape，再右键打开菜单；最后点测试菜单「退出」。

正常退出后脚本核验进程结束、删除本进程 `.invalid` 域名的虚拟凭据并清理隔离配置／缓存。30 分钟未退出时，测试看门狗结束该测试进程，脚本继续清理并记录失败；不会结束日常程序。报告保存在 `tests/artifacts/tray-menu-manual.json`，事件只用于辅助核对顺序。脚本始终将 `humanVerification` 留为 `pending`；`hiddenTrayPanel` 和 `multiMonitorVisual` 始终留为 `not_verified`，由用户反馈另行形成实际人工验收结论。原生右键事件本身不能证明点击来自隐藏面板，多屏视觉不在这三步里自动认定通过。

维护时可运行 `./tools/tray-menu-acceptance.ps1 -CheckManual`，程序化检查同一手动入口的配置首次打开／关闭／复用、Escape 重开、真实提供商凭据查询隔离及退出清理；报告为 `tests/artifacts/tray-menu-manual-check.json`，明确标记 `automationOnly: true`，保留人工项目待验。三个模式共用脚本并互斥执行。脚本在启动新参数前检查调试二进制标识，避免旧版本不识别参数而误启正式初始化。

人工结果补记（2026-10-08）：用户通过双击入口测试后反馈未见明显问题。测试 PID 30788 的报告记录 5 次真实托盘右键、2 次配置动作及随后获得焦点、2 次模型切换、1 次退出；正常 exit=0，虚拟凭据和隔离配置／缓存清理均已核验，测试进程已结束。未获得隐藏面板位置、多屏视觉和每个手工步骤的逐项确认，因此只补上述实际操作证据，不把这些项目全部标为人工通过。详细反馈与边界见 [人工验收记录](../tests/artifacts/tray-menu-manual-preparation.md)。

## 托盘左键规则更新（2026-10-08）

后续功能改动将左键改为单击切换划词图标、系统识别的快速双击切换模式。右键菜单行为及窗口生命周期不变；单击／双击计时和退出取消由 `app/tray.rs` 负责，细节见 [托盘模式提示](tray-mode-feedback.md)。本页此前「左键保持不变」指窗口整理当时的范围，不表示后续功能仍采用单击切换模式。新手势需另行人工确认。
