## 2026-09-12 异常恢复与重试

发现并修复：原“重新翻译”直接重新捕获当前选区，且前端缺少连续点击保护。现在：
- 翻译失败时，在内存保留这一请求的 TranslationRequest（原文、上下文、模式等）。重试只读取当前前台窗口身份以安全显示浮层，直接复用原文，不重新读取选区。
- 重试携带失败请求编号；Rust 在协调锁内核对最新请求及失败状态，原文只能领取一次，并创建新请求编号。新捕获和取消清除旧重试原文；旧模型结果仍受会话编号及最新结果存储双重保护。
- 读取选区本身失败时仍需重新捕获，且会核对失败请求编号。
- 重试提交期间禁用原按钮，三次连续点击仅调用一次。IPC 失败后按钮恢复并显示简短提示；成功后主动同步最新状态，避免等待丢失的事件。
- 现有模型超时配置与提示保留，没有增加自动重试或额外模型请求。

验证：91 项前端测试、162 项 Rust 测试通过（1 项在线测试跳过）；新增 Rust 原文/上下文完整保留、编号不匹配不可领取、只能领取一次、取消清除测试。浏览器回归覆盖连点防重、IPC 拒绝恢复、请求编号传递、旧结果晚到不覆盖，原有阅读、解释和公式回归通过。浏览器和 Vite 服务自动关闭。本轮使用模拟错误与响应，未调用真实模型、未验证实际断网后端到端重试。

## 2026-09-12 本地 HTTP 异常恢复补验

使用绑定 127.0.0.1 随机端口的测试服务器，调用真实 reqwest HTTP 请求和生产 read_model_response：
- 已收到响应头但正文停滞：在请求期限到达后返回正常超时提示。
- Content-Length 未满足即断开：显示“模型响应接收中断，请重试”，避免底层技术错误直接展示。
- 完整 503 响应保留状态与正文，供原有服务错误处理使用。
- 同一客户端随后请求返回成功；四次测试请求均发送相同的合成原文。
- 无监听服务的本地端口连接失败返回既有可操作提示。

两个接口分支（OpenAI-compatible 与 Anthropic）共用正文读取错误处理。没有改动超时时长、凭据或自动重试策略。164 项 Rust 测试通过，1 项在线验收跳过。测试服务器线程与连接在测试结束时关闭，不使用真实模型、不读取用户密钥、不保存原文。这验证的是 HTTP 传输层及错误处理，并不等价于完整桌面点击重试的端到端验收。
