# macOS 移植起步计划

状态：菜单栏交互已于 2026-10-19 按用户决定调整为「单击切换划词图标开关，右键菜单切换模式」。独立原型与专用 CI 已建立；原型已直接复用现有配置页组件、样式及品牌字体。共享配置、模型传输及连接测试已接入 Mac 原型，配置可保存，密钥通过独立 Keychain service 存储；快捷键取词和翻译浮层仍待后续开发。Mac 编译与真机交互的验收分别记录。

依据：当前 Translay 0.5.0 源码及现有托盘、选区、浮层验收记录。本文安排开发顺序与验收边界；具体平台接口以 Mac 原型验证结果为准。

## 首轮目标与安排

第一轮按 3～5 个工作日安排，前提是有可用的 macOS 开发和交互验收环境。目标是交付一份 Mac 交互规则、一套可运行的系统交互原型和应用兼容性记录。

核心路径：在目标应用选中文字 → 使用全局快捷键 → 获取当前选区 → 在附近显示原文或固定译文 → 原应用继续接收输入。

| 阶段 | 预计投入 | 交付物 | 完成条件 |
| --- | --- | --- | --- |
| A. 交互与平台边界梳理 | 半天～1 天 | 交互规则、系统依赖清单、验收场景 | 菜单栏、模式、开关、连续操作的行为均有明确规定；依赖清单能对应到当前源码 |
| B. Mac 系统交互验证 | 2～4 天 | 可独立编译运行的最小 Tauri 验证入口、兼容性记录 | 快捷键、取词、浮层、焦点保护有真机证据，失败情况和回退边界有记录 |
| C. 根据证据确定正式移植范围 | 首轮结束时评审 | 平台拆分范围、首版支持应用、后续任务顺序 | 明确可复用部分、需要原生实现的部分、已知限制及下一阶段估算 |

上表是工程估算，未计入取得 Mac 环境、安装工具链、开发者账户办理或外部服务等待。首轮结束后重新估算正式移植工作量。

当前开发主机是 Windows；可用 Mac 的芯片架构、系统版本和访问方式待确认。当前主机可以完成阶段 A，并准备阶段 B 的场景与样本文字。阶段 B 的原生交互结论需要在 macOS 上取得。

## 第一项实际开发：建立最小 Mac 验证入口

已建立 `experiments/macos-spike/` 独立开发入口，使用独立应用标识与内存状态。构建和运行说明见该目录的 `README.md`；本节保留首个里程碑的完整验收范围。

| 顺序 | 开发内容 | 可检查的结果 |
| --- | --- | --- |
| 1 | 使用当前项目同一代 Tauri／React 技术栈，建立 Mac 编译和启动入口 | 在实际 Mac 上构建并启动；记录系统、芯片、工具链和构建命令 |
| 2 | 菜单栏图标与独立内存状态：单击切换划词开关，右键菜单选择日常／学习模式，并提供配置和退出入口 | 每个主键单击只切换一次开关，快速两次恢复原值；右键及次要点按不改变开关；模式仅随明确的菜单选择更新 |
| 3 | 创建单个使用 Mac 原生窗口控制的配置窗口，接入真实辅助功能授权状态 | 可打开、关闭并重开同一入口；关闭窗口后菜单栏仍工作；原生按钮、拖动区域与授权反馈可检查 |
| 4 | 在同一原型接入快捷键取词和显示原文的浮层 | 至少先在 TextEdit 或一个实际支持选区读取的应用中跑通，再扩展到首轮应用清单；分别记录取词、焦点保留和点击浮层后的行为 |

第 2 步中的开关用于验证菜单栏手势与状态更新，正式的自动划词监听在后续阶段接入。第 3 步复用正式版翻译与模型表单的视觉组件，接入窗口控制、入口与权限反馈；模型表单已接入共享配置和连接测试，浏览器入口继续保持只读预览。

原型使用独立开发数据和样本文字。状态与固定内容可以作为测试样例；授权状态、菜单事件、选区读取与窗口行为均由真实系统接口提供。验收记录明确区分样例内容与真实平台能力。

### 已核对的最小边界

- `models.rs` 的 `CapturedSelection` 持有 `ForegroundContext`，后者包含 Windows HWND；原型的编译入口需要与该依赖分开。
- `lib.rs` 和 `app/mod.rs` 当前直接加载 Windows 模块；主程序整体的条件编译整理安排在原型结果确认之后。
- `capture_session.rs` 的请求编号与取消逻辑不直接依赖系统 API，可以作为后续共享逻辑的依据。
- `app/tray.rs` 已有划词开关与模式更新操作，但混合了 Windows 手势、动画和系统状态更新；先在 Mac 原型验证输入语义，再确定提取范围。
- `SettingsView.tsx` 的表单与品牌布局可以复用；原型先验证原生窗口控制与授权反馈，完整接入时保持现有表单状态和 IPC 语义。
- 屏幕位置、选区几何与缩放的转换约定由原型记录和真机结果确定，再用于平台接口设计。

这项任务的交付物是 Mac 原型源码、可重复的构建／运行说明，以及真实操作结果记录。目前已实现菜单栏状态逻辑、原生菜单与配置窗口代码、辅助功能授权查询／请求，以及分别构建两种 Mac 架构的工作流。快捷键取词、翻译浮层和自动划词尚未接入。编译检查、模拟事件与真实交互结果分别记录，不将代码存在视为原生验收通过。

## A. Mac 交互规则

菜单栏手势遵循用户于 2026-10-19 确定的分配：单击负责划词图标开关，模式切换放在右键菜单。其余规则供首轮验证使用，后续按真机结果调整。

| 入口或操作 | 建议行为 | 验收要点 |
| --- | --- | --- |
| 单击菜单栏图标 | 每个有效主键单击切换一次划词图标开关，并更新状态图案 | 不等待双击判定；不切换模式；一次按下／松开只执行一次 |
| 快速或连续点击菜单栏图标 | 按普通单击逐次处理，每次根据最新状态切换开关 | 两次有效单击会切换两次、回到原状态；不会触发模式切换；旧回调不覆盖新状态 |
| 右键菜单栏图标 | 打开菜单，提供模式选择、设置、模型入口和退出等操作 | 打开菜单不改变划词开关；系统次要点按与主键单击正确区分 |
| 模式切换 | 在右键菜单中明确选择日常或学习模式，以选中标记显示当前状态 | 选择同一模式不重复翻转；各界面状态一致 |
| 划词图标开关 | 自动划词阶段接入菜单栏单击，并同步菜单中的开关项 | 关闭后撤销候选、隐藏按钮；快捷键翻译仍可使用 |
| 设置、模型入口、退出 | 从菜单栏右键菜单访问 | 退出中不再执行迟到操作；关闭配置窗口后仍能从菜单重新打开 |
| 快捷键翻译 | 对当前目标应用的当前选区发起请求 | 组合键选择需检查系统及常用应用冲突，后续可配置 |
| 翻译浮层 | 显示于选区附近；无可靠选区几何信息时使用鼠标位置 | 保留来源应用的焦点与选区，边缘位置不遮住主要操作 |
| 浮层关闭与失焦 | 区分来源应用焦点、浮层阅读状态和明确关闭操作 | 展开、复制、滚动、关闭有一致行为；迟到结果不重新打开已关闭内容 |
| 文本双击、三击、拖动、键盘扩选 | 读取来源应用实际提供的选区，结合输入事件确定读取时机 | 以最终选区为准，避免把点击次数直接当作选区内容 |

首个基础可用版围绕快捷键翻译安排；自动划词图标进入后续阶段时，接入单击开关与菜单开关的正式行为。原型阶段用隔离的开关状态验证单击和连续操作。

模式、模型、开关的业务状态与更新命令可以共享；Windows 托盘的单双击分类与 Mac 的逐次单击／右键菜单各自实现。保存、状态同步、请求过期隔离、退出取消等规则在两端保持一致。

### 配置界面适配建议

配置界面继续复用现有 React 的侧栏、翻译选项、模型表单、品牌配色及保存／连接测试状态，按平台提供窗口控制与系统能力。

原型已直接引用 `src/settings/SettingsView.tsx`、`src/settings/settings.css` 和 `src/shared/uiFonts`，无需复制或重做现有设计。共享视图默认保持 Windows 行为；Mac 使用原生标题栏，关闭 WebView 内自绘窗口按钮及拖动区域，追加系统权限内容，并为小窗口提供滚动。Mac 样式仅补充这些平台内容与系统字体回退，品牌字体仍优先使用仓库内的 WOFF2 资源。CI 路径过滤也覆盖 `src/settings/**`，共享界面修改会触发 Mac 构建检查。

当前界面在 `src/settings/SettingsView.tsx` 中绘制右上角最小化和关闭按钮；`src-tauri/src/app/windows.rs` 创建 680 × 570 的无边框、不可调整大小的配置窗口。现有关闭请求已转为隐藏窗口，这项产品行为可以保留。模型服务官方页面的打开操作目前在 `src-tauri/src/app/commands.rs` 中直接调用 Windows Shell。

| 部分 | Mac 适配建议 | 验收重点 |
| --- | --- | --- |
| 窗口控制与标题栏 | 使用 macOS 原生窗口控制，调整顶部留白、可拖动区域和侧栏品牌位置 | 窗口按钮、文字与拖动区域不重叠；输入框和按钮可正常点按；窗口能力与启用的原生按钮一致 |
| 关闭、最小化与重新打开 | 关闭配置窗口后继续驻留菜单栏；从右键菜单恢复同一配置入口 | 保存内容正确保留；重复打开不生成多份窗口；退出命令与关闭窗口行为分开处理 |
| 键盘与编辑操作 | 验证 Command 系列复制、粘贴、全选、撤销，以及 Tab 导航；配置窗口支持 Command-W 关闭 | 表单可完整使用键盘操作；Command-Q 进入应用退出流程；编辑快捷键不被全局快捷键拦截 |
| 系统权限 | 在翻译页补充辅助功能授权状态与打开系统设置入口 | 未授权、授权后重新尝试、运行期间撤销授权的状态准确；权限问题与模型连接问题分别反馈 |
| 凭据与系统链接 | API Key 使用 Keychain，保留现有掩码展示与按提供商保存的行为；官方页面交给默认浏览器打开 | 保存、读取、删除及切换提供商正确；完整密钥不进入普通配置文件；系统链接在 Mac 上可打开 |
| 内容区与 WebView 显示 | 按加入原生标题栏后的内容区检查尺寸，保留品牌字体和主要布局，在 WKWebView 中验证输入控件、焦点、滚动与长报错 | 表单、保存区、长模型名和错误提示完整可见；字体与缩放可读；必要时调整间距与滚动容器 |

原型阶段验证共享配置样式、原生窗口控制、辅助功能状态和设置入口。原生程序的模型表单已接通配置保存、连接测试、Keychain 与系统链接；浏览器入口明确标注只读预览。共享层与平台适配边界见 `docs/shared-settings-architecture.md`，配置页继续回归 Windows 的现有行为。后续基础可用版阶段接入取词、翻译浮层和完整窗口生命周期。该阶段的验收证据包含 Mac 配置页截图及真实键盘、关闭、重开操作记录。

## B. Mac 原型实施顺序

1. 记录环境：Mac 芯片、macOS 版本、工具链及测试应用版本，建立独立的开发与验收数据目录。
2. 建立可独立编译的最小 Tauri 验证入口，用隔离状态验证单击逐次切换开关、右键开菜单和菜单内切换模式，并检查触控板次要点按与 Control-点按是否正确进入右键路径。现有主程序直接依赖 Windows 模块，原型入口需要有明确的编译边界。
3. 实现辅助功能授权状态检查，验证未授权、授权后重新尝试、运行期间撤销授权的反馈。
4. 接入全局快捷键，取得来源应用及其当前选区，记录成功、空选区、超时或不支持的结果。
5. 为直接读取失败的场景验证受控 Cmd+C 回退，处理来源应用变化和用户同时复制的竞争。
6. 接入浮层，优先复用现有 React 内容；验证 Tauri 与原生窗口策略组合下的焦点、交互和显示位置。
7. 使用固定文本验证请求替换、关闭后迟到结果、菜单操作与浮层操作交错等场景。
8. 汇总真实应用结果，按直接取词、剪贴板回退、暂不支持分别记录支持范围。

原型阶段可以使用原文和固定译文。正式模型请求在系统交互路径确认后接入。

### 首轮验收场景

| 场景 | 要取得的证据 |
| --- | --- |
| Safari、Chrome、Preview 中可选文本的 PDF、一个文字编辑器 | 每个应用分别记录取词方式、完整性、选区几何信息和失败情况；扫描 PDF 的 OCR 属于独立需求 |
| 拖选、双击选词、三击选择、键盘扩选 | 比较最终选区与实际捕获文字，记录应用自身的选区语义差异 |
| 未授权、授权后、撤销权限 | 明确反馈与恢复路径，不把授权失败显示为模型失败 |
| 浮层显示及按钮操作 | 核实来源应用焦点、选区保留、继续输入及浮层操作；分别记录仅显示和实际点击后的行为 |
| 连续选择两段文字，或请求后立即关闭 | 旧结果不覆盖新结果；关闭内容不被迟到结果重新打开 |
| 剪贴板回退及用户同时复制 | 恢复只在仍有本次写入归属时执行；记录文字、图片、文件等格式的保留范围及限制 |
| 菜单栏单击、快速连续点击、右键及触控板次要点按 | 每个有效主键单击切换一次开关，两次切换恢复原值；右键只打开菜单；各输入均不自动切换模式 |
| 右键菜单反复选择模式、菜单操作与取词交错 | 模式只按显式选择更新；菜单开关项与单击状态一致；旧操作不覆盖最新状态 |
| 配置窗口的标题栏、授权状态和菜单重开入口 | 原生窗口控制可用；授权提示与实际系统状态一致；关闭配置后菜单栏继续工作且可重开 |
| 屏幕边缘、全屏应用、另一桌面、外接屏（可用时） | 首轮记录架构风险和可用范围；完整发布验收补齐承诺支持的显示场景 |

原生行为以真机操作和结果记录为依据。合成事件、浏览器组件测试、Windows 测试通过，均不能单独证明 Mac 焦点、权限或系统菜单行为。

## C. 后续正式移植顺序

### 1. 按原型结果拆分平台能力

把选区、来源应用、剪贴板、窗口、凭据等系统能力放在清晰的平台入口后面。共享数据类型不暴露 HWND、POINT 等 Windows 类型。接口范围由原型实际需要确定，保持改动集中。

Windows 继续使用其现有手势和系统实现；Mac 的主键单击及右键菜单选择调用同一业务状态更新命令。平台拆分后完成现有检查，并复核 Windows 单击、连续双击、右键取消、退出中迟到回调等关键场景。

### 2. 交付快捷键翻译基础版

接入现有翻译、模型配置、缓存、日常／学习模式、详细解释和 React 界面；补齐 Keychain、单实例和右键菜单入口。配置界面按上文建议适配原生窗口控制、辅助功能状态、键盘、系统链接和关闭／重开行为。构建配置改为平台可用形式，能力配置明确覆盖 Mac 窗口，检查 WKWebView 下的样式与交互。

该阶段交付可运行的 Mac 测试包、已验证的支持应用清单、已知限制和 Windows 回归记录。具体投入在首轮评审后确定。

### 3. 增加自动划词图标与连续操作支持

在快捷键基础路径稳定后，实现选区变化、鼠标与键盘事件、划词图标出现／撤销、滚动后隐藏、跨应用切换等逻辑。补充触控板、拖动和连续选词的真机验收，并检查空闲时的系统资源占用。

### 4. 完成发布准备

根据实际用户设备确定首发架构，验收结论按架构记录。需要覆盖 Intel 与 Apple Silicon 时，分别验证对应构建。补齐 Mac 图标、app/dmg、CI、签名、公证以及首次安装授权引导；Windows 与 Mac 的支持范围分别记录。

完整版本早期可参考约 3～6 周的规划范围；该范围尚未经过真机原型验证，后续以首轮结果和最终支持范围重估。
