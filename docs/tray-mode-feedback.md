## 左键单击／双击规则（2026-10-08）

托盘单击改为切换现有「划词图标」偏好；快速双击切换日常／学习模式。划词开关与右键菜单复用同一持久化／运行状态更新函数；关闭仍会撤销划词候选并隐藏入口，快捷键独立保留。双击沿用现有模式保存、前端同步和提示窗口，不改变提示配色、尺寸、定位或动画，不新增 UI。

点击分类在 `app/tray.rs` 内集中处理。使用 Windows 的 `TrayIconEvent::DoubleClick`，第一下松开后按 `GetDoubleClickTime()` 等待系统双击间隔，再认领单击；这段等待使用已有 Tokio runtime 的异步计时，不阻塞窗口线程。双击取消待确认单击，忽略该双击的最后一次松开；正常下一次按下表示独立点击，会结算此前单击，并恢复在图标外丢失松开的状态。右键取消尚未确认的单击后按原流程打开菜单。计时回调携带代次，在窗口线程认领，旧回调不能误认领新单击；状态锁只用于决定，不持锁执行保存或原生窗口操作。

旧 280ms 模式点击防抖从提示模块移除，避免吞掉两次合法且快速的双击；点击分类和一次执行规则由托盘模块负责，提示模块只处理显示与 generation 消失隔离。`ShutdownCoordinator` 与最终 Exit 都停止待确认点击，迟到事件和计时回调不能在退出后修改偏好或再次显示提示。显式启用现有 Tokio 的 time feature，没有升级或新增依赖。

相关系统依据：[GetDoubleClickTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdoubleclicktime)、[Windows 双击事件顺序](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-lbuttondblclk)。同时核对项目锁定的 tray-icon 0.24.1 Windows 消息映射；双击实际为 down → up → double → up。

原生工具继续复用 `tools/tray-menu-acceptance.ps1`。新增的是在真实窗口线程向正式托盘处理函数注入 Tauri 事件，检查运行开关、落盘、模式、连续双击、右键取消和退出期间迟到输入；不把这些合成事件标为真实系统鼠标双击。人工实测可双击现有 `tools/tray-menu-manual.cmd`，单击后右键看「划词图标」勾选变化，双击后看模式提示且勾选保持不变。此前人工结果对应旧手势，不能沿用为新单击／双击规则通过。

## 两行悬停提示（2026-10-08）

正式托盘的原生悬停文字精简为 `模式：日常/学习` 与 `图标：开启/关闭` 两行。图标状态指划词入口的开关，沿用 `selection_icon_enabled`；提示不再展示应用名和模型名，避免模型名称拉宽窗口。Windows 原生提示负责字体、留白与 DPI 显示，应用仅更新文字，不另外创建悬停窗口或缩小系统文字。

`app/tray.rs` 集中生成与更新文字和图案：启动读现有配置；单击和右键开关复用同一更新入口；模式保存后沿用现有表面同步，若该同步失败则单独尝试更新托盘。更新不持配置锁，不改变已保存状态；退出中跳过更新。隔离人工测试仍额外保留“手动测试（临时数据）”标识，因此该调试提示比正式提示多一行。

两种模式与两种开关的四个组合由已有 Rust 托盘单元测试覆盖；预览用于检查紧凑两行外观。原生 Windows 悬停尺寸、隐藏图标面板及跨屏 DPI 效果仍需实际验收。相关原生接口：[NOTIFYICONDATAW 的标准提示文本](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw)。

## 托盘图案表示开关（2026-10-08）

划词图标开启时保留原托盘标志，关闭时使用选定的“侧向叠合”标志，再次开启恢复原图。程序启动读取已保存的开关；右键菜单与单击走同一链路；双击切模式只更新两行提示中的模式，开关形态保持对应状态。系统深浅主题继续使用现有检查线程，但关闭状态下换主题也会选择折起资源。应用图标、划词按钮及其他界面资源不变。

`refresh_tray_state` 通过项目锁定的 Tauri `with_inner_tray_icon` 在窗口线程决定图案与文字更新；配置和主题在执行时读取，避免调用方排队前的旧开关覆盖新状态。图案的短过渡状态仅在托盘模块内保存，规则见下节。构建继续使用既有资源生成工具，不重写原图与 ICO。

原生更新失败向调用方返回并记录错误，不回滚已保存的开关，也不保留“正在更新”门禁；下一次实际状态更新可再次调用。主题变化保留原有三秒检查机制。退出检查在调度前与窗口线程执行时各进行一次，退出后的排队回调不再更新图案或文字。

原生验收继续使用 `tools/tray-menu-acceptance.ps1`，在隔离测试已有探针中记录原生 setter 成功后的图片字节与提示文字，检查关闭状态启动、单击/菜单开关、两种模拟主题、排队回调读取新状态、双击与退出隔离。该探针只在隔离 debug 验收中存在，不加入正式程序的状态。它验证系统接口成功接收更新，不能代替真实隐藏面板悬停与多屏视觉验收。

## 折叠／展开的短过渡（2026-10-08）

第一次松开鼠标后立即启动视觉预览：开启时沿“侧向叠合”的轴折起，关闭时展开。普通完整动作 260ms，使用 quadratic ease-out，起步更明显、末尾柔和收住；不透明度不变，不增加放大、弹跳、浮窗或声音。实际划词开关仍等待系统单击／双击判定，动画不等待它，预览不撤销划词候选、不改运行开关或落盘。确认单击后沿用原保存与运行状态更新，已播放的动作不重新启动。原生两行提示始终反映实际配置，确认前保持原文字。启动直接呈现已保存状态；右键开关沿用普通过渡。

检测到双击后，以当前实际姿态继续向稍紧的第 24 姿态收拢（约 90ms），随后舒回保存的形态：开启时约 220ms 回到原 T，关闭时约 140ms 回到折起端点。没有额外定格等待；达到收紧姿态即衔接返回。实际模式只切换一次，划词开关保持不变。关闭状态下第一下会预展开，若随后形成双击，就从当时姿态接管收紧并最终恢复关闭形态；不宣称程序能在第一下预知双击。

`app/tray.rs` 内的 `FoldAnimation` 记录最后成功提交的姿态、目标、主题与代次；私有 `FoldIntent` 区分实际配置、待判定预览、双击收紧／返回。新的相反目标从当前姿态反转，普通剩余时长按行程缩短；模式文字或主题刷新不重启动作，双击事件显式接管一次新动作。主题变化使用当前姿态的另一配色。右键取消待判定单击并顺滑恢复保存的形态；取消回调携带点击代次，旧回调不能取消新预览。外部配置变化优先于预览或双击反馈。

同一姿态与同一主题不调用图案 setter；同一文字不调用提示 setter。开始运动只启动帧调度，不额外重画当前图案，单击确认也不会重画已抵达的端点。这修复此前开始前的多余刷新，但真实闪烁是否消失仍需人工检查。

仅有运动时才在既有 Tokio runtime 中启动短异步计时任务，约每 16ms 请求下一帧，并等待 `windows::on_window_thread` 完成真实 setter。窗口线程依据实际经过时间选择姿态，忙碌时跳过过期帧，不积压回调，不持状态锁执行原生操作。反转产生新代次，旧任务下一次回调退出；正常结束后没有持续动画轮询。保留原有三秒主题检查。

提交或调度失败会停止当前运动、记录错误并保留最后成功姿态，下一次实际状态刷新可重试，不自动循环重试或修改配置。退出沿用 `ShutdownCoordinator` 及最终 Exit 的托盘停止入口，同时停止待确认单击和折叠；迟到帧检查退出和代次后跳过系统操作。原有窗口隐藏、菜单会话、配置保存及其他窗口行为不变。

生成工具的 `--tray-animation-only` 只输出两个 RGBA 条带，每种主题 19 个普通中间帧加 4 个收紧姿态，合计 184 KiB，比上一版增加 32 KiB；普通中间帧和两个端点字节保留，没有引入图片解码依赖。Rust 测试验证 260ms 曲线、提前预览、确认不重播、双击双向收紧／返回、峰值重入、旧取消代次、失败恢复和退出。现有原生工具验证预览发生在配置改变前、开始与重复刷新不重画同一图案、两种保存状态的双击收紧／恢复、连续独立单击及既有窗口链路。真实 Windows 外壳的平滑度、闪烁、隐藏面板及多屏 DPI 仍由人工检查，程序化 setter 成功不代表这些视觉项已经通过。
